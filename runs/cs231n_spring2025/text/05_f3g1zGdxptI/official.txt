Example: Histogram of Oriented Gradients (HoG)

Divide image into 8x8 pixel regions
Within each region quantize edge
direction into 9 bins

Example: 320x240 image gets divided
into 40x30 bins; in each bin there are 9
numbers so feature vector has 30*40*9 =
10,800 numbers

Lowe, “Object recognition from local scale-in variant features”, ICCV 1999
Dalal and Triggs, "Histograms of orient ed gradients for human detection ," CVPR 2005

Convolution Summary
Input: Cin x H x W
Hyperparameters:
Kernel size: KH x KW
Number filters: Cout
Padding: P
Stride: S
Weight matrix: Cout x Cin x KH x KW
giving Cout filters of size Cin x KH x KW
Bias vector: Cout
Output size: Cout x H’ x W’ where:
H’ = (H – K + 2P) / S + 1
W’ = (W – K + 2P) / S + 1
Stanford CS231n 10 th Anniversary

Common settings:
KH = KW (Small square filters)
P = (K – 1) / 2 (”Same” padding)
Cin, Cout = 32, 64, 128, 256 (powers of 2)
K = 3, P = 1, S = 1 (3x3 conv)
K = 5, P = 2, S = 1 (5x5 conv)
K = 1, P = 0, S = 1 (1x1 conv)
K = 3, P = 1, S = 2 (Downsample by 2)

Summary
- ConvNets stack CONV,POOL,FC layers
- Trend towards smaller filters and deeper architectures
- Trend towards getting rid of POOL/FC layers (just CONV)
- Historically architectures looked like
[(CONV-RELU)*N-POOL?]*M-(FC-RELU)*K,SOFTMAX
where N is usually up to ~5, M is large, 0 <= K <= 2.
- But recent advances such as ResNet/GoogLeNet have
challenged this paradigm
